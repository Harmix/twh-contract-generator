# TWH — прототипы Trading Ways Hub

## Рабочее пространство сделки (прототип 0.2) — `deal/`

Живая версия: https://harmix.github.io/twh-contract-generator/deal/

Сквозной поток из архитектуры TWH v0.1 (Бекмырза, 20.09.2026) и созвона 16.09.2026:
рамочный договор → спецификация → счёт → оплата → CMR → закрытие.
Данные вводятся один раз и протекают в каждый следующий документ.

Как показать за пять минут: «Сбросить демо», потом переключать роль сверху
(Поставщик / Покупатель) и нажимать то, что предлагает блок «Ваш ход».

Что внутри:

- Рамочный договор с лимитом, как реально работает завод. Конкретика идёт спецификациями.
- Спецификация на несколько товаров (просьба завода), контроль остатка лимита.
  Документ повторяет реальную форму завода: 17 пунктов, упаковка, цена партии, реквизиты сторон.
- Согласование обеими сторонами: любая правка сбрасывает согласие второй стороны.
- График платежей из условий договора: 30/70, 50/50, 100%, аккредитив, постоплата, эскроу.
- Счета выставляются сами по событию: аванс при согласовании, остаток после CMR.
- Payment Digital Twin: покупатель отмечает перевод с референсом, поставщик подтверждает,
  платёж сверяется со счётом. Реквизиты фиксируются снимком на момент платежа.
- Эскроу-режим: средства «держатся» до подписи покупателя в графе 24 CMR, потом раскрываются.
- Отгрузка закрыта, пока не пришёл аванс — система объясняет почему.
- Хронология: каждое действие с автором и временем.
- Документы (договор, спецификация, счёт, CMR) на двух языках, выгрузка в DOCX.

Чего нет сознательно: аккаунтов и сервера. Обе стороны в одном браузере через переключатель
ролей, данные хранятся локально. Это демо для банка и завода, а не продакшен.
Следующий шаг после их «да» — бэкенд по архитектуре v0.1 (модульный монолит, Postgres).

| Файл | Что внутри |
|---|---|
| `deal-engine.js` | Команды сделки и state machines, без DOM. Недопустимый переход — понятная ошибка. |
| `deal/index.html` | Интерфейс: роли, «Ваш ход», вкладки, документы. |
| `verify-deal.mjs` | 65 тестов потока: роли, статусы, суммы, лимит, эскроу, документы, форма спецификации завода. |

# Генератор договора поставки (прототип 0.1)

Заполняет международный договор поставки TradingWays Hub v1.1 по ответам на форму:
часть полей подставляется автоматически, часть сопровождается рекомендацией.
Ветвление по Incoterms, направлению поставки и категории товара.

## Как запустить

Открыть `index.html` в браузере. Сборка не нужна, сервер не нужен, интернет не нужен.
Все зависимости лежат в папке, внешних запросов приложение не делает.

Живая версия: https://harmix.github.io/twh-contract-generator/

Кнопка «Заполнить примером» подставляет сделку по вафлям Алматы → Ташкент,
чтобы показать заводу за десять секунд.

## Что делает

**Считает и подставляет**

- номер договора `TWH-2026-00001`
- сумму и сумму прописью на русском и английском
- документы к отгрузке: набор зависит от категории товара, транспорта и маршрута
- сертификат происхождения: СТ-1 для СНГ, Form A для дальнего зарубежья
- применимое право, арбитраж и место арбитража по направлению поставки
- срок годности для пищёвки вместо гарантийного срока для промтоваров
- сторону, отвечающую за растаможку вывоза и ввоза
- текст условий оплаты по выбранному пресету (30/70, 50/50, предоплата, аккредитив, эскроу, постоплата)

**Предупреждает**

- CIF выбран для автотранспорта
- сумма выше $50k без аккредитива или эскроу
- пищевая продукция без срока годности
- DAP и DDP внутри ЕАЭС различаются слабо, потому что импортной очистки нет

**Показывает открытые вопросы**

Спорные места не выдаются за факт, а подсвечиваются синим блоком над договором.
Открыт один: английский текст статей 6.2, 5.1.8, 5.1.9 и 12.6 переведён нами
и ждёт вычитки юриста.

Четыре закрыты письмом Бекмырзы от 06.09.2026 и зафиксированы в `RULES.settled`:
СТ-1 внутри ЕАЭС идёт по запросу Покупателя (обязателен только вне ЕАЭС),
внутри ЕАЭС ставим «таможенное оформление не требуется, единая таможенная территория»,
НДС по умолчанию 0% экспортный, страховка при DAP остаётся необязательной.

## Файлы

| Файл | Что внутри |
|---|---|
| `rules.js` | Слой знаний. Incoterms, маршруты, документы, право, HS-коды, пресеты оплаты, открытые вопросы. Единственный источник правды по юридической логике. |
| `engine.js` | `derive()` считает следствия, `buildContract()` собирает текст, сумма прописью RU и EN. Без DOM. |
| `docx.js` | Сборка OOXML. Работает и в браузере, и в Node. |
| `index.html` | Форма, живое превью, кнопки. Только отображение. |
| `verify.mjs` | 81 тест. Запуск: `node verify.mjs` |
| `jszip.min.js` | JSZip 3.10.1, вшит локально. MIT / GPLv3, Stuart Knightley. Нужен только для выгрузки в DOCX. |

Правило: юридическая логика правится в `rules.js`, формулировки статей в `engine.js`,
внешний вид в `index.html`. Смешивать их не нужно, иначе следующая правка договора
превратится в поиск по всему проекту.

## Проверка

```
node verify.mjs
```

81 тест: страховка по Incoterms, растаможка по маршруту, состав документов,
право и арбитраж по всем направлениям, сумма прописью (включая склонения
«один доллар / два доллара / пять долларов»), даты, ветвление срок годности
против гарантии, перебор всех 378 комбинаций маршрут × Incoterms × категория × транспорт.

DOCX дополнительно проверен на открываемость: файл распаковывается,
XML всех частей валиден, python-docx читает 98 абзацев и 9 таблиц.

## Чего пока нет

Регистрации, аккаунтов, базы данных, эскроу-счёта, ЭЦП, согласования правок
между сторонами. Прототип генерирует договор, а не заменяет платформу.
Следующий шаг зависит от реакции завода.
